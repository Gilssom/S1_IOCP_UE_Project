# 관측·격리 부하 기준선과 개선 기록 — 2026-11-16

## 범위와 환경

- Windows 로컬, Debug GameServer, IOCP 작업 스레드 5개, 루프백 연결. Unreal 렌더링이나 외부 인터넷은 부하 생성기에 포함되지 않는다.
- 실제 GameDB 대신 `S1LootTest_20261001`, 포트 7778, 별도 작업 폴더와 로그를 사용했다. 관리자가 테스트 스키마에 빈 Account 테이블을 만들었고, 테스트 계정·캐릭터 행은 테스트 DB에 남아 있다. 테스트 비밀번호는 부하 생성기 프로세스 메모리에서만 생성했다.
- 서버 데이터는 현재 저장된 MainMap 내비게이션·스폰·포털 자료의 복사본을 사용했다. 이동은 패킷으로 좌표를 보내는 합성 이동이며 UE 충돌·실제 조작·렌더링 부하를 검증하지 않는다.
- JSON 결과와 서버 지표는 `C:\Users\user\Documents\Unreal IOCP Server\checkpoints\LoadBaseline_20261116`에 보존했다. 각 시험은 단일 실행이므로 용량 보장이나 통계적 결론이 아니다.

## 현재 구현한 관측 기반

- 서버는 기본적으로 작업 디렉터리의 `Logs/ServerMetrics.jsonl`에 5초마다 스냅샷을 추가한다. `GAMESERVER_METRICS_FILE`로 별도 파일을 지정할 수 있다. 파일 쓰기는 서버 메인 루프에서 수행한다.
- 누적 접속·종료, 현재 연결, 수신 패킷 ID별 개수·수신 바이트, 송신 바이트, 디스패치 실패·시간 버킷, 잘못된 프레임 개수, DB 풀 크기·가용·획득 실패·반납까지의 시간 버킷, 지역별 플레이어·몬스터·미완료 Room 작업, 공격 승인·거부 및 몬스터 적중을 기록한다. 프로세스 CPU 누적 시간과 작업 집합 메모리도 기록한다.
- UTC 밀리초, 프로세스 ID, 시작 시각, 가동시간을 함께 기록한다. 서로 다른 프로세스/시작 시각의 누적 카운터를 그대로 차감하면 안 된다. 패킷 ID 1000–1063만 개별 집계하고 나머지는 전체 수신량에만 포함한다.
- DB checkout 시간은 DB 연결을 빌린 뒤 반납하기까지의 전체 시간으로, SQL 단일 쿼리 시간과 다르다. 디스패치 시간은 핸들러 호출 시간이며 Room 비동기 작업 완료나 클라이언트 왕복 지연이 아니다. Room 작업 수에는 현재 실행 중인 배치가 포함된다. 5초 샘플은 짧은 피크를 놓칠 수 있다.
- 비밀번호·패킷 본문·채팅·계정명을 이 지표에 넣지 않는다. 기존 텍스트 로그는 별개다. 지표 파일 자동 회전/보존 정책, 패킷 종류별 송신량, SQL 작업별 시간, Room 대기시간 분포와 장애 경보는 아직 없다.

## 시험 결과

계정·캐릭터는 순차적으로 생성하고, 이후 32개 연결이 동시에 로그인한다. 성공한 클라이언트는 마을 이동 → 포털 → 필드 이동 → 1.6초 간격 기본 공격을 수행한다. 아래 결과는 각각 별도 실행이다.

| 조건 | 동시 로그인 성공 | DB 연결 부족 응답 | 필드 진입 | 비고 |
|---|---:|---:|---:|---|
| 변경 전, DB 풀 4 | 4/32 | 28 | 4 | 비밀번호 검증 중 DB 연결 유지 |

| 검증 중 연결 반환, 시험용 DB 풀 8 | 32/32 | 0 | 32 | 최종 코드 재시험 |

최종 풀 8 시험에서는 성공 로그인 32건의 응답시간 p95가 444.372ms, 포털 승인 32건 p95가 3.327ms, 전투 응답 256건 p95가 61.796ms였다. 32개 로그인은 동시 실행했지만 계정 생성은 순차적이다. 변경 전 로그인 p95에는 빠르게 실패한 응답 28개가 포함되므로 성공 응답 p95와 직접 비교할 수 없다. 동일 PC에서 DB·클라이언트·서버가 자원을 공유한다.

`GAMESERVER_DB_POOL_SIZE`는 1–32의 선택 설정이며 기본값은 기존 4개를 유지한다. 풀 8 결과는 이 로컬 시험의 근거이며, 운영 기본값 변경이나 DB 서버 연결 한도는 별도 측정이 필요하다. 로그인 해시 계산은 여전히 IOCP 작업 스레드에서 수행하므로 동시 로그인 지연과 DB 후속 조회 경쟁이 남는다.

## 측정으로 확인하고 수정한 항목

1. 로그인 성공 경로가 비밀번호 검증 중 DB 연결을 보유했다. 계정 조회 직후 바인딩을 해제하고 연결을 반환하며, 인증 성공 후 캐릭터 조회를 위해 다시 획득하도록 변경했다. 잘못된 비밀번호·정상 로그인·동시 중복 계정 접속 회귀를 격리 DB에서 확인했다.
2. 길이가 0인 프레임 하나가 IOCP 작업 스레드에서 무한 반복됐다. 격리 시험에서 3초 동안 서버 CPU 시간이 약 3.02초 증가하고 지표에 대량의 실패 디스패치가 기록됐다. 최소 헤더보다 작은 프레임을 거부하고 연결을 끊도록 수정했다.
3. 분할 수신에서 새로 읽힌 바이트 수만 파싱해 남은 버퍼의 완성된 패킷을 처리하지 못했다. 2바이트씩 분할한 로그인 프레임은 변경 전 시간 초과, 변경 후 응답을 확인했다. 범위 밖 패킷 ID 65535도 안전하게 연결 종료한다.

- 장시간 부하, 반복 실행에 따른 편차, 더 많은 클라이언트, 실제 UE 클라이언트 부하, 패킷 송신 부분 완료, DB 장애/재연결, 원격 네트워크 및 패키지 시험은 별도 검증이 필요하다.
