# Astra 다음 작업 기획을 위한 구현 현황 인계 초안

작성일: 2026-09-23  
대상: `Unreal 5.8 S1 Project 기획_Astra`  
목적: 다음 **한 단계**의 작업 명세를 정하기 위한 사실관계와 결정 요청. 이 문서는 신규 콘텐츠 구현 승인서가 아니다.

## 1. 판정 기준

- **구현 확인**: 현재 소스·에셋 또는 구현 기록에서 확인한 기능. 플레이 검증을 뜻하지 않는다.
- **도구 검증**: 빌드, 내비게이션 스모크 테스트, MCP 조사 등 결과가 문서에 기록된 것.
- **사용자 플레이 확인**: 사용자가 직접 완료했다고 보고한 PIE 테스트. 이번 문서 작성 시 로그를 재검토하거나 PIE를 다시 실행한 결과와 구분한다.
- **미완료**: 설계안만 있거나 현재 슬라이스 밖에 있는 기능. 이전 버전의 테스트 성공을 현 버전의 증거로 승격하지 않는다.

## 2. 최근 기획안 대비 완료도

| 항목 | 현재 상태 | 근거와 범위 |
| --- | --- | --- |
| Dusk 평지 접지·서버/클라이언트 캡슐 기준 통일 | **구현 확인 + MCP 조사 완료** | MainMap 테스트 바닥 상면 `Z=-0.5 cm`, 캡슐 반경 `28 cm`·반높이 `62 cm`, 서버 평지 중심 `Z=61.5 cm`. 클라이언트 `AS1DuskMinion` 기본값과 공통 정의를 맞췄고, 임시 BP 인스턴스의 충돌 바닥이 `Z=-0.5 cm`임을 확인했다. 서버 스폰·추적·복귀에서 같은 평지 중심을 사용한다. |
| Dusk 시각 표현 | **부분 완료** | `S1DuskMinion` C++ 기반 Blueprint 사용. 현재 메쉬 스케일 `0.7`, 상대 yaw `+90°`, 상대 Z `-62 cm`. 스켈레탈 시각 바운드는 충돌 바닥 아래로 내려갈 수 있으며, 이를 서버 접지 오차로 해석하지 않는다. 공격 종료 연결, 피격/사망 표현 품질은 별도 검증·개선이 필요하다. |
| MainMap 벽 회피 추적·복귀 | **구현 + 도구 검증 + 사용자 플레이 확인** | 최근 기획에서는 후순위였지만, 이후 사용자 지시로 범위를 확장했다. 저장된 MainMap Recast를 `S1NAV 2`로 내보내 서버가 A* 경로와 funnel 경로를 사용한다. 74 노드·250 간선 내보내기 및 직선/벽 모서리/벽 반대편 스모크 테스트 기록이 있다. 사용자가 2026-09-23 두 클라이언트 PIE에서 벽 우회 추적과 우회 복귀를 확인했다. |
| 벽 너머 공격·피해 방지 | **구현 + 사용자 플레이 확인** | 서버 Dusk 공격 가능성 판단에 경로 거리를 반영한다. 사용자가 두 클라이언트 PIE에서 벽 반대편 공격·피해가 발생하지 않음을 확인했다. 모든 동적 장애물·지형에 대한 일반 보증은 아니다. |
| Dusk 전투·HP·사망·재생성·재접속 | **첫 수직 슬라이스 구현 + 사용자 회귀 확인** | Dusk HP, 추적, 공격, Terra 기본 공격 타격, 피해, 사망/재생성 흐름이 있다. 사용자가 두 클라이언트 PIE의 HP·사망·재생성·재접속 회귀를 완료했고 문제를 보고하지 않았다. 이번 인계에서 별도 로그 감사나 패키징 실행은 하지 않았다. |
| Terra A–D 기본 공격 | **기존 4타 구현 유지** | 최신 입력 버퍼 규칙을 기준으로 한다. 옛 `ComboWindow` 설명으로 회귀시키지 않는다. 적중 시점 `500/530/450/530 ms`와 Dusk `420 ms`는 실제 접촉 프레임 확정값이 아니라 임시값이다. |
| Q, E, 방어, 회피 | **Q는 연출 중계만 / 나머지는 보류** | Q의 서버 권위 이동·충돌·피해는 미완료. E 비활성, 방어 보류, 회피 애니메이션 미확보. 기존 AbilityId `11002`의 GuardAura 의미를 Q로 바꾸지 않는다. |

최근 Astra 초안의 `0.66` 스케일·`33×60` 캡슐·`-90°` yaw는 **당시 제안치**다. 실제 바닥/애셋 조사와 이후 사용자 승인에 따라 위의 `0.7`, `28×62`, `+90°`, `Z=61.5`가 현재 구현값이므로, 제안치로 되돌리는 작업을 요청하지 말 것.

## 3. 검증 증거의 경계

1. 내비게이션 구현 기록에는 `S1ExportNavigation` 성공, 74 노드/250 간선, 경로 스모크 테스트, GameServer Debug·Release 빌드와 Release 기동의 DB/계정 초기화가 기록돼 있다.
2. 2026-09-23 사용자가 두 클라이언트 MainMap PIE에서 (a) 벽 우회 추적, (b) 벽 너머 공격·피해 없음, (c) 추적 포기 후 벽 우회 귀환, (d) 두 클라이언트 HP·사망·재생성·재접속 회귀를 완료했다고 보고했다. **이번 인계에서 로그나 영상으로 독립 재확인하지 않았다.**
3. 현 버전의 인증된 패키징 클라이언트 회귀, 경사/언덕 대응, 동적 장애물 대응, 다른 맵의 내비게이션은 검증 또는 구현 근거가 없다.
4. 전체 솔루션의 깨끗한 일괄 재빌드는 기존 `ServerCore/IocpCore.cpp` 호출 문제와 생성 단계 경합 때문에 막혔던 이력이 있다. 영향을 받은 GameServer 빌드 성공과 동일시하지 말고, 별도 유지보수 과제로 관리한다.

## 4. 다음 명세를 쓰기 전 고려할 기술·콘텐츠 간극

- **서버 권위의 범위**: 현재 IOCP 서버가 Dusk의 이동/공격 가능성과 피해·HP 결과를 결정한다. 다만 `C/S_COMBAT_ACTION` 중계와 타격 처리를 완전한 행동 승인/거부, 요청자 예측 복구, 범용 스킬·피해 프로토콜로 간주하면 안 된다. `AuthorityAndCombatIdContract.md`의 승인/Reject 패킷은 아직 적용 완료된 사실이 아니다. 프로토콜·DB 변경은 별도 승인 범위를 명시해야 한다.
- **정적 MainMap 경로 데이터**: 저장된 Recast에서 내보낸 그래프다. 맵 또는 NavMesh 변경 시 다시 내보내야 한다. 동적 장애물, 경사/언덕의 서버 Z, 다중 맵 경로는 이번 단계에서 제외했다.
- **타격 시점과 반응**: Terra A–D 및 Dusk 접촉 시간은 잠정값이다. Dusk 공격-종료 사이의 단일 노드 애니메이션 전환, HitReact의 additive 처리, Terra/Dusk 사망 표현은 영상 기준 품질 검토가 필요하다. 실제 접촉 프레임을 에디터에서 확인하거나 사용자 타임코드를 받아 확정해야 한다.
- **시각적 콘텐츠 범위**: 새로운 몬스터·스킬·아이템보다 기존 Terra–Dusk 1종 슬라이스의 읽기 쉬운 피격/HP/사망 연출과 재현 가능한 촬영 시나리오가 포트폴리오 가치에 더 직접적일 수 있다. 이는 구현 담당의 **제안**이며 콘텐츠 우선순위 결정은 기획/사용자 몫이다.
- **문서 정합성**: `KnightCombatDesign.md`, `ProjectExecutionGuide.md` 등의 오래된 미래형 표현은 현재 Dusk 첫 슬라이스 구현 상황과 다를 수 있다. 다음 기획은 날짜가 최신인 구현 기록과 실제 소스를 우선 대조해 작성해야 한다.

## 5. Astra에 요청할 다음 작업 기획

한 프롬프트에 Q, AI, DB, 연출을 모두 넣지 말고, 다음 두 후보 중 **하나의 좁은 수직 과제**를 선택해 명세해 달라.

### 권장 후보 A — 전투 행동 승인/거부 계약 정리

현재 Terra A–D와 Dusk 1종만 대상으로 서버가 요청을 수락/거부하는 기준, 클라이언트의 예측 모션 정리, 중복 요청·연타·타임아웃 처리, 관전자에게 전달할 연출 시점을 확정한다. 기존 `C/S_COMBAT_ACTION`과 실제 서버 구현을 조사한 후 필요한 최소 프로토콜 변경 여부를 결정한다. **데이터베이스·Q·새로운 피해 타입은 이번 명세에서 제외**하는 것을 권장한다. 계약이 서버 권위 데모의 신뢰도를 좌우하므로 구현 관점의 1순위 제안이다.

### 후보 B — Terra–Dusk 타격·피격 표현 정밀화

실제 접촉 프레임을 계측해 4타와 Dusk 공격 판정 시점을 튜닝하고, 적중 피드백과 공격 종료/피격/사망 모션을 정리한다. 서버 판정과 클라이언트 연출의 경계를 유지한다. Dusk `HitReact_Front`가 additive이므로 사용 방식 또는 대체 애셋을 먼저 확인한다. 영상 촬영 목표가 최우선이라면 이 후보를 먼저 배치할 수 있다.

두 후보 모두 인수 조건에는 **두 클라이언트 PIE**, 벽 앞/뒤·연타·중단·사망·재접속 회귀, 서버/클라이언트 로그에서 중복 피해와 오류 없음, 실제 실행하지 않은 검증의 명확한 표기를 넣어 달라. 필요한 에셋과 사용자가 직접 해야 하는 작업은 명세 첫머리에 별도 게이트로 제시해 달라.

## 6. 기획/사용자 결정 요청

1. 다음 1회 작업을 **A(행동 승인·거부)**와 **B(타격·피격 표현)** 중 어느 쪽으로 우선할지. 구현 관점 권장은 A, 촬영 시연이 임박했다면 B가 합리적이다.
2. B를 택한다면 Terra A–D 및 Dusk `Attack_A` 실제 접촉 프레임/영상이 있는지. 없으면 구현 담당이 에디터에서 잠정값을 측정하고, 수치는 후속 수정 가능하게 둘 것.
3. 새 애니메이션·VFX·사운드가 필요하면 정확한 S1 애셋 경로와 포트폴리오 사용 권한을 확인할 것. `UE5_RPG`는 읽기 전용 레퍼런스이며 무승인 이관 금지.

경사면/언덕 대응은 사용자가 후순위로 미뤘다. Q 서버 이동·충돌, E·방어·회피, DB·퀘스트·아이템도 이번 다음 1회 명세에서 자동 포함하지 말 것.
